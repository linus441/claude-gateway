【核心问题】装完之后第一次打开 Claude，会不会被地区限制卡住？

  不会。直接进去。

  装的瞬间，安装脚本已经把「第三方模式」的配置文件写好了，
  所以 Claude 从第一次启动起就在 3p 模式，整个"检查账号地区"
  的分支根本不执行。


  首次打开时的实际表现
  ------------------------------------------------------------
  "only available in certain regions"    不出现
  登录页 / 账号验证                        不出现
  "选择部署模式" 引导页                    不出现
  主界面                                   直接进入（You're here!）
  模型下拉框                               空的，0 个


  为什么会这样（三个开关，写在两个 json 里）
  ------------------------------------------------------------
  Claude-3p\claude_desktop_config.json
      deploymentMode = "3p"

  Claude-3p\configLibrary\<uuid>.json
      disableDeploymentModeChooser = true   跳过部署模式选择
      modelDiscoveryEnabled        = true   让 Claude 自己去拉模型清单
      coworkEgressAllowedHosts     = ["*"]  放开网络出口

  这两个文件是 Claude 自己的，原本它只在你登录成功后才生成。
  全新机器上它卡在登录页，永远不生成 —— 死循环。
  所以安装脚本用 bootstrap.js 主动把它们造出来。


  唯一的"但是"
  ------------------------------------------------------------
  界面进得去，但下拉框里没有模型可选。
  包里的模型表是空的（models.json = []），这是故意的：
  不预设任何模型，也不带任何 key。

  要用模型，装完必须做四步：
    1. 启动 Magpie 并登录（或用别家上游）
    2. 面板 → 上游页 → 点「自动填充」
    3. 勾选要用的 → 「加进模型表」→ 模型页「保存并应用」
    4. 模型页「重启 Claude」

  做完第 4 步，下拉框里才有东西。


================================================================
  这个包具备的全部能力
================================================================


一、部署
----------------------------------------------------------------
  · 双击「一键安装.cmd」，安装网关 + Magpie（Claude Desktop 由单独安装器安装）：

      提权 → 复制网关和 Magpie → 随机生成密钥
      → 写 3p 配置 → 设开机自启 → 建桌面图标 → 启动网关 → 开面板
  · 自带 node.exe，目标机器不需要预装 Node
  · 不带任何原环境内容：模型表为空，上游只留内置的 magpie，
    网关密钥在安装时随机生成，不是固定值
  · 可重装：再次安装时 models.json / upstreams.json 会保留，
    不覆盖你已经配好的内容


二、网关（监听 127.0.0.1:15722）
----------------------------------------------------------------
  · /v1/messages    按 Anthropic 协议把请求转发到多个上游
  · /v1/models      给 Claude 的模型下拉框供数据
  · Base URL 智能处理：末尾的 /v1 自动去掉，
                     /anthropic、/openai 这类前缀保留
  · 上游热生效：面板改完立刻生效，不用重启网关
  · 多上游并存，按模型条目指定走哪个
  · 内置上游 Magpie（127.0.0.1:3425），走 WorkBuddy 额度，不需要填 key
  · 可接任意兼容 Anthropic 协议的中转：DeepSeek、Agnes、自建服务
  · 协议自动识别：保存上游时探一次 /v1/messages，自己判断对方说的是
    Anthropic 还是 OpenAI 协议，不用手选
      - 403（分组未开通 /v1/messages）、404 都判定为 OpenAI 兼容
      - 判定结果存进 upstreams.json，改显示名不会触发重探
  · OpenAI 兼容上游由网关负责双向翻译
      - 请求：system / 多模态图片 / tool_use / tool_result 全部换算
      - 响应：文本流、tool_calls 流式参数都还原成 Anthropic 事件
      - 推理模型（o1/o3/o4/gpt-5 至 gpt-9）自动改用
        max_completion_tokens，并且不发送 temperature / top_p


三、模型管理
----------------------------------------------------------------
  · 自动遵守 Claude 的硬命名规则 claude-<档位>-<数字>
  · 四个档位：opus / sonnet / haiku / fable，每档只能有一个"默认"
  · 「自动命名」：按上游返回的真实模型名，自动分配 Claude 认的名字
  · 「自动填充」：拉上游模型列表、逐个探测可用性、自动分档位和显示名
  · 显示名可改（labelOverride），不影响实际转发的模型 id


四、控制面板（浏览器界面，4 个页签）
----------------------------------------------------------------
  模型页
    · 增删改、设默认、保存并应用、重启/打开 Claude
  上游页
    · 添加 / 编辑 / 删除上游
    · 测试连通性
    · 自动填充（拉列表 + 探测 + 分档）
  还原点页
    · 最近 7 份快照，自动去重
    · 复原前会先存一份当前状态，防止越退越乱
  日志页
    · 实时请求记录，能看每次请求走了哪个上游、用了哪个模型

  另有顶栏 5 个状态卡，和「自建配置档」按钮（3p 配置出问题时一键重建）


五、托盘程序
----------------------------------------------------------------
  右键菜单：
    · 打开控制面板
    · 状态显示（运行中 / 已停止，含端口）
    · 重启网关
    · 重启/打开 Magpie
    · 恢复原装 Claude 设置（移除网关的 3p 配置）
    · 重启/打开 Claude Desktop
    · 打开网关日志
    · 打开配置目录
    · 退出

  机制：
    · 单实例互斥，不会重复起
    · 托盘点「退出」会写 .tray-off 标记，之后开机自启不会再拉起它
    · 日志超过 1MB 自动轮转
    · 点面板的叉 = 只关窗口，网关和托盘还在跑（设计如此）


六、自启与快捷方式
----------------------------------------------------------------
  · 启动文件夹放一个 vbs，开机无窗口拉起托盘和网关
  · 桌面一个 .url 快捷方式，带自定义图标（不依赖 COM 创建 lnk）
  · 所有脚本用相对路径定位自己，整个目录搬到别处照样能用


七、安全
----------------------------------------------------------------
  · 网关密钥安装时随机生成，存在 gateway\gw-key.txt
  · 只监听回环地址，局域网其他设备连不上
  · 源码里不写死任何第三方 key，内置上游的 key 留空，
    只从环境变量读
  · 不收集、不上报任何数据


八、卸载
----------------------------------------------------------------
  双击「一键卸载.cmd」，先列清单，输入 YES 才动手。

  删：
    · 网关 / 托盘 / Magpie 进程（先停再删，避免文件占用）
    · %LOCALAPPDATA%\ClaudeGateway 整个目录
    · 启动文件夹的 Claude Gateway Tray.vbs
    · 桌面的 Claude 网关.url
    · Claude 的 3p 配置（claude_desktop_config.json + 网关建的那份配置档）
    · 注册表启动项 / 计划任务（如果存在过）

  不删：
    · Claude Desktop 本身
    · 你的聊天记录
    · CC Switch 等其他工具建的配置档（_meta.json 里别的条目会保留并改指向）

  模型表里有内容时，会先备份到桌面 Claude网关-卸载备份-<时间>\；
  是空的就直接删，不留垃圾。

  安全保护：只删目录名是 gateway / ClaudeGateway 的路径，
  删除前再校验一次路径里带 claude+gateway，对不上一律拒绝。

  不做的                          说明
  ----------------------------------------------------------------

================================================================
  前提条件与常见失败
================================================================

  必须满足
  ----------------------------------------------------------------
  · 必须是商店 MSIX 版 Claude（PackageFamilyName 含 pzs8sxrjxfjjc）。
    部署包装的就是这个版本。
  · 机器上不能留着旧的 Squirrel 版（%LOCALAPPDATA%\AnthropicClaude）。
    它读的是另一套路径，起了照样卡地区限制。安装脚本会检测并提醒。

  3p 配置没写进去怎么办
  ----------------------------------------------------------------
  表现：Claude 还是卡在登录页，或提示 only available in certain regions。

  办法一：面板点「自建配置档」→ 确认 → 再点「重启 Claude」
  办法二：手动跑
      & "$env:LOCALAPPDATA\ClaudeGateway\gateway\node.exe" `
        "$env:LOCALAPPDATA\ClaudeGateway\gateway\bootstrap.js"

  跑完完全退出 Claude（任务栏右键 → 退出）再打开。

  面板显示「网关未运行」
  ----------------------------------------------------------------
  看 %LOCALAPPDATA%\ClaudeGateway\gateway\gateway.log 最后几行。
  多半是端口 15722 被别的程序占了。

  下拉框是空的
  ----------------------------------------------------------------
  正常。模型表是空的，走上游页「自动填充」→ 加进模型表 →
  保存并应用 → 重启 Claude。

  卸载时目录删不掉
  ----------------------------------------------------------------
  托盘还在跑，文件被占用。重启机器再跑一次卸载脚本即可，
  其余部分已经删完了。


================================================================
  和 CC Switch 的区别
================================================================

  CC Switch 支持更多工具（Codex、Gemini CLI 等），功能更全。

  这个包只管 Claude Desktop 一家，定位是：
    · 代码全透明，配置就是几个可读的 JSON
    · 想改什么直接改文件，不藏在数据库里
    · 没有协议转换，也不做故障转移

  两者不能同时接管 Claude Desktop，只能二选一。
